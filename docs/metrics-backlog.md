# 指標の積み残しと決めたこと

2026-10-12 の調査で挙がった指標を入れたときに、見送ったことと決めたこと。
数値は同日の実データ (`~/roam`、直近6ヶ月) で手計算したもので、アプリの集計とは期間の区切りが少し違う。

## 前提: データにあるもの・ないもの

| データ | org の行数 | 使えるもの |
|---|---|---|
| `:Effort:` | 125 | 見積もり精度 |
| `DEADLINE` | 48 | 期限の遵守率 (件数は少ない) |
| 見出しのタグ | 35 | 作業の種類で分けるには足りない |
| `:CREATED:` / 状態変更ログ | 1 / 0 | なし。着手前の待ち (作ってから最初の CLOCK まで) は測れない |

着手前の待ちを測りたくなったら、`org-expiry` などで `:CREATED:` を付ける運用が要る。

## まだ入れていないもの

調査で挙がった指標はすべて入れた。入れたときに見送ったもの:

- **期限遵守率は実データでは出ない**: DEADLINE のある DONE は 2021〜2022 年の39件だけで、どの範囲でも測れないのでゲージを隠している。DEADLINE を使い始めれば出る
- **見積もり精度は実データでは出ない**: :Effort: のある DONE は 2023-01〜2025-07 の80件だけで、プリセットの範囲には入らない
- **作業の密度は日をまたぐセッションを開始した日に数える**
- **実績の時間は25分未満の CLOCK を含まない**: パーサーがポモドーロ未満の CLOCK を落とすので、Task Size と見積もり精度の実績は少なめに出る
- **XmR の材料は暦の始まりからの週**: 暦は Activity や記事の日付からも始まる。タスクより前に Activity があると、その週は完了 0 件として入る (実データではタスクが最も古いので起きない)

## 決めたこと

- **XmR の中心と幅は中央値**: リードタイムは数件の長いタスクで平均が大きく振れ、平均 ± 2.66 × 平均移動範囲 (Wheeler の標準) では、外れ値の後のふつうの週がすべて「平均の下に8期間」と判定された。中央値 ± 3.14 × 移動範囲の中央値にしている
- **XmR の下限が 0 なら下側の兆しは見ない**: 値は負にならないので、0 で止めた下限は限界線として扱わない
- **XmR の移動範囲の中央値が 0 なら平均で引く**: 同じ値が続くと幅が 0 になり、少しでも動いた点がすべて限界線の外になるため、平均 ± 2.66 × 平均移動範囲にする
- **今日を含む期間は欠けた期間**: まだ終わっていない日を含むので、XmR の限界線に入れない
- **モンテカルロ予測は入れてから外した**: 過去の週ごとの完了数を引き直して、TODO を終える週数と次の4週の完了数を確率で出すもの。要らないと判断して外した
